# Changelog

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
версии — [SemVer](https://semver.org/lang/ru/).

Номер версии в заголовке окна совпадает с версией файла (`1CUpdate.exe` → свойства → «Версия файла»).

## [2.0.0] — 2026-11-06

### Добавлено

- **WPF-интерфейс** (`wpf/1CUpdate.Wpf`): тёмная тема из шаблона WpfUiKit, шапка,
  KPI-карточки, вкладки «Результаты / Журнал», сглаженные закругления и тёмный title bar.
- **Один самодостаточный exe**: `publish\1CUpdate.exe` (~64 МБ) — внутри рантайм .NET 8,
  скрипт установки, PsExec и standalone-воркер. .NET на ПК не требуется.
- **Встроенный воркер** (WinForms exe, ~1 МБ): именно он копируется на целевые ПК через
  `psexec -c`, поэтому режим «копировать exe на ПК» работает и для WPF-сборки.
- **`build-wpf.ps1`** — сборка и публикация WPF-версии (`-Publish`, `-Publish -Folder`).
- **`sign.ps1`** — подпись exe сертификатом code signing; раздел про SmartScreen в README.
- **Выбор компьютеров из AD**: асинхронная загрузка дерева OU и списка; выбор OU сразу
  подгружает компьютеры.

### Исправлено

- Падение `NullReferenceException` при открытии диалога «Из AD…» (событие чекбокса
  срабатывало до создания TreeView).
- Зависание окна при недоступном контроллере домена — LDAP-запросы вынесены в фон,
  ошибки показываются понятным текстом.
- Поля ввода стали компактнее (24 px вместо 28), уплотнены отступы.

## [1.1.0] — 2026-11-05

### Добавлено

- **Выбор компьютеров из Active Directory деревом OU**: слева структура подразделений
  (загружается по мере раскрытия), справа компьютеры выбранного OU, галочка «включая вложенные OU»,
  фильтр по имени, «Отметить все».
- **Проверка версии до установки**: на целевом ПК читается список установленных платформ
  (реестр, 32- и 64-битные ветки) и сравнивается с целевой. Если версия уже стоит —
  установка не запускается, ПК получает статус **«Уже установлена»**.
- **Проверка результата после установки**: статус «Готово» ставится только если версия
  подтверждена чтением реестра на самом ПК; иначе — «Ошибка» с причиной.
- **Отдельный канал прогресса**: процесс на ПК пишет шаги в `<dl>\<ПК>.<id>.progress.txt`
  (свой файл на каждый запуск). Окно читает и его, и вывод PsExec, дубли отбрасывает.
- **Самоочистка**: копия программы, которую PsExec кладёт на целевой ПК
  (`C:\Windows\1CUpdate.exe`), удаляется после работы через административную шару `C$`
  от указанной учётной записи.
- **Автоматический повтор**, если файл на ПК занят прошлым процессом: снимается блокировка
  (`taskkill`) и запуск повторяется.
- **Поддержка IP-адресов** наравне с именами ПК.
- **Серые подсказки-примеры** в полях (`\\server\share\distr\1c`, `DOMAIN\admin` и т. д.)
  и всплывающие подсказки почти ко всем элементам окна.
- **Своя иконка окна** (раньше в панели задач могла показываться стандартная заглушка .NET).
- **Диагностика**: аварийный след `%TEMP%\1CUpdate-crash.log` на целевом ПК и пошаговый
  файл прогресса при ошибках.
- `.gitignore`, `LICENSE` (MIT), `CHANGELOG.md`.

### Изменено

- Зашитые в код домен, шары и логин заменены на пустые поля с примерами; введённые значения
  сохраняются в `%APPDATA%\1CUpdate\settings.ini`.
- Отчёт по завершении: «Итого: N ПК · успешно · уже стояло · с замечаниями · ошибок · время».
- Версия приложения — 1.1.0.

### Исправлено

- **Зависание «Выполняется…»**: убран «уборщик» копии exe, запускавший `cmd.exe` — тот
  наследовал канал вывода PsExec и не давал процессу завершиться.
- **«Итог не подтверждён» при реально выполненной установке**: чтение файла прогресса
  ломалось при перезаписи файла и при совпадении размера с прошлым запуском; добавлено
  финальное дочитывание и уникальное имя файла на каждый запуск.
- **Пустые параметры при первом запуске**: скрипт-разбор `param()` не срабатывал из-за
  несуществующего типа в AST; добавлено резервное чтение параметров из текста скрипта.
- **Ошибка «фильтр поиска недоступен» в AD** при пустом поле «Имя содержит» (`name=**`);
  добавлены корректный фильтр и подключение через текущий домен.
- **Запись журналов на шару**: каталог `-dl` теперь создаётся автоматически (и приложением,
  и скриптом), иначе журнал молча уходил в `%LOCALAPPDATA%` на самом ПК.
- **Скрипт 1.09**: поиск установленных платформ через реестр вместо `Get-WmiObject Win32_Product`
  (без многоминутного согласования MSI и без WMI), разрядность через
  `[Environment]::Is64BitOperatingSystem`, исправлены проверка «64-бит на 32-битной ОС»
  и два присваивания вместо сравнения.
- Занятый exe при сборке больше не мешает: он переименовывается в `1CUpdate.old.exe`.

## [1.0.0] — 2026-11-05

Первый выпуск.

- Окно: список ПК, параметры скрипта (`-dd`, `-dl`, `-ip`, `-dp`, `-iod`), таблица результатов,
  журнал, отчёт CSV/TXT.
- Запуск через PsExec от указанной учётной записи, 1–64 потоков, кнопка «Стоп».
- Три способа доставки скрипта: копирование exe на ПК (`-c`), выкладка `.ps1` на шару,
  внешний `.ps1`.
- Скрипт `1C8InstallAndUninstall` и PsExec (`x86`/`x64`) вшиты в один `.exe`.
- Сборка одним скриптом `build.ps1` через `csc.exe` (.NET Framework 4.x), без внешних зависимостей.
